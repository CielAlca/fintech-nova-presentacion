👤 1. DANIEL DRAGÚN

Infraestructura AWS, Despliegue y api-transacciones

☁️ Infraestructura AWS
AMI Ubuntu Server 26.04 x86_64 e instancia t3.small (2 vCPUs y 2 GiB de RAM) con asignación automática de IP pública.
🛡️ Reglas del Security Group
• Inbound 22 (SSH) acotado con /32 a la IP del admin 190.231.148.10.
• Inbound 443 (HTTPS) abierto a 0.0.0.0/0.
• Puerto 80 cerrado sin excepciones (ni para redirigir).
• Outbound abierto a todo el tráfico.
🚀 Automatización de Despliegue (deploy.ps1 / deploy.sh)
Flujo en 5 fases: conexión SSH → instalación remota de Docker → transferencia segura por SCP de .env y SQL → docker compose pull y up -d → Smoke tests con curl a los 7 endpoints (200 OK).
⚡ Microservicio api-transacciones (Go 1.22)
Binario estático ultra ligero con CGO_ENABLED=0 (< 20 MB). Enriquecimiento con API externa de GeoIP (ipapi.co) e instalación obligatoria de ca-certificates en Alpine.

👤 2. NICO LÓPEZ

Gateway Ingress, TLS, NGINX y admin-panel

🚪 Gateway Ingress web (NGINX)
Único punto de entrada público con mapeo de puertos del host 443:443. Garantiza el aislamiento total de las APIs internas.
🔒 Terminación TLS en el Borde
Cifrado HTTPS con server.crt y server.key generados en memoria al arrancar la EC2. Tráfico interno en HTTP plano por rendimiento. Alerta esperada de certificado autofirmado validada por la cátedra.
🧭 Configuración de NGINX (nginx.conf)
• Directiva resolver 127.0.0.11 valid=30s con variable dinámica $upstream (evita caídas si una API tarda en iniciar).
• server_tokens off; para hardening.
• Directivas rewrite para entregar rutas limpias a las APIs.
📊 7º Microservicio: admin-panel (Web2)
Requisito especial de grupo de 5 integrantes. Muestra topología de red en tiempo real, nómina y estado de salud. Corre en puerto 80 interno dentro de fintech-net sin exponerse al host.

👤 3. LUCAS GASTIABURÚ

Red fintech-net, MariaDB 11.8 y api-tarjetas

🐳 Red Compartida Docker (fintech-net)
Creación de red bridge fintech-net con subred 172.18.0.0/16. Resolución automática de nombres por DNS interno de Docker (127.0.0.11:53) sin usar IPs fijas.
🗄️ Base de Datos MariaDB 11.8 (Aislamiento Lógico)
1 sola instancia de motor con 5 esquemas lógicos independientes (db_clientes, db_tarjetas, etc.), en lugar de 5 motores separados para no agotar la RAM de la t3.small.
💾 Persistencia y Volúmenes
• Named Volume (db_data): En /var/lib/mysql para datos permanentes.
• Bind Mount (:ro): De ./init-scripts en solo lectura para scripts SQL iniciales.
💳 Microservicio api-tarjetas (.NET 8 Minimal API)
C# asíncrono con MySqlConnector. Multi-stage: SDK de compilación descartado → Runtime aspnet:8.0-alpine (~110 MB) con usuario no-root app.

👤 4. CLAUDIA ALCA

api-clientes, Healthchecks, api-pagos y Resiliencia

🐍 Microservicio api-clientes (Python 3.11 / Flask)
Aislamiento en entorno virtual /opt/venv, usuario no-root appuser (UID 1000) contra escape de contenedor, y variables de entorno PYTHONDONTWRITEBYTECODE=1 y PYTHONUNBUFFERED=1.
🩺 Healthchecks Nativos sin herramientas extras
Uso de librerías del lenguaje estándar (urllib.request en Python y http.get en Node), sin instalar curl en la imagen final reduciendo la superficie de ataque.
🟢 Microservicio api-pagos (Node.js 20 / Express)
Instalación limpia determinista con npm ci --omit=dev --ignore-scripts y ejecución bajo usuario no-root nativo node (UID 1000) sobre Alpine.
🛡️ Resiliencia ante Fallos Externos
Llamada a la API externa de tipo de cambio en bloque try/catch: si cae o hay timeout, se guarda en db_pagos con monto_usd en null y responde 201 Created sin romper el ABM.

👤 5. JULIÁN TORRES

api-facturas, Memoria JVM, Secretos y Cierre

☕ Microservicio api-facturas (Java 21 / Spring Boot)
El servicio con mayor exigencia de hardware del stack. Requiere contención estricta de recursos en Compose: 384M de RAM y 0.50 CPU.
⚡ Optimización Extrema de Memoria JVM
Flags de tuning en el Dockerfile: -Xms128m -Xmx256m -XX:+UseG1GC para liberar memoria rápido y evitar que el Out-Of-Memory Killer de Linux mate los contenedores.
🏗️ Multi-Stage Obligatorio en Java
Descarta Maven y el JDK completo (~850 MB); en la imagen final solo corre el app.jar sobre un Temurin JRE Alpine liviano (~180 MB).
🔐 Preguntas "Para Pensar" y Cierre
• Secretos fuera de Git: .env protegidos por OWASP y transferidos vía SCP cifrado.
• Certificados en runtime: Generados al bootear (evita quemar claves en Docker Hub).
• Ventajas y Mejoras: Despliegue reproducible en < 2 min. Próximos pasos: CI/CD con GitHub Actions + AWS ALB.
